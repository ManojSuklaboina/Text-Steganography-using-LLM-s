# Secret Data Hiding in LLM Text Generation

A Large Language Model (LLM)-based text steganography project that explores
hiding secret information inside text generated by Large Language Models.

This project implements two different approaches for generating steganographic
text:

1. Method 1 - Character-Level / Bit-Level Embedding using Huffman Coding
2. Method 2 - Single Character-Based Word Generation and Retrieval

The main objective is to investigate the trade-off between embedding capacity,
text naturalness, and reliable extraction of the hidden information.

---

## Project Overview

Traditional text steganography generally uses an existing cover text and
modifies it to hide secret information.

This project explores a different approach in which the Large Language Model
itself generates the text containing the hidden information.

The two implemented methods use different hiding mechanisms:

### Method 1

The secret message is converted into a predefined Huffman-coded binary
representation. The resulting bitstream is embedded into LLM-generated text
using two predefined character groups.

### Method 2

Each character of the secret message is represented by a generated English
word whose first character corresponds to the secret character.

---

# Method 1 - Character-Level / Bit-Level Embedding

## Description

This Method uses Huffman coding to convert the secret message into a binary
bitstream.

The LLM then generates candidate text. Each generated word is examined
character by character and converted into bits according to predefined
character groups.

### Group 0

    I S H L C F W P V X J

### Group 1

    N R D U M Y G B K Q Z

Characters belonging to Group 0 represent:

    0

Characters belonging to Group 1 represent:

    1

Characters that do not belong to either group are skipped during bit
extraction.

---

## Method 1 Embedding Process

The process is:

    Secret Message
          |
          v
    Huffman Encoding
          |
          v
    Binary Bitstream
          |
          v
    LLM Text Generation
          |
          v
    Candidate Words
          |
          v
    Group 0 / Group 1 Bit Matching
          |
          v
    Stego Text

The secret message is first converted into the predefined Huffman bit
representation.

The remaining bits are then embedded sequentially.

For every generated candidate word:

1. The characters belonging to Group 0 and Group 1 are converted into bits.
2. Characters outside both groups are ignored.
3. The resulting bit sequence is compared with the beginning of the remaining
   secret bitstream.
4. The word is accepted only if its generated bit sequence matches the
   required beginning of the remaining bitstream.
5. If the word does not match the required bits, that word is NOT considered
   for embedding.
6. The process continues until the secret bitstream has been embedded.

This sequential matching mechanism prevents a word from contributing
incorrect bits to the embedded message.

---

## Important Embedding Rule

A generated word is not automatically accepted.

For example, if the remaining secret bits are:

    101100...

and a candidate word produces:

    1011

then the word can be accepted because its encoded bits match the beginning
of the remaining sequence.

The remaining sequence becomes:

    00...

However, if a candidate word produces:

    0110

it does not match the required beginning and therefore the word is rejected.

This rule is central to Method 1.

---

## Method 1 Extraction

During extraction, the generated payload words are examined character by
character.

For each character:

    Group 0 -> 0
    Group 1 -> 1
    Other characters -> skipped

The extracted binary sequence is then decoded using the same predefined
Huffman mapping.

The process is:

    Stego Text
        |
        v
    Extract Words
        |
        v
    Character Examination
        |
        +---- Group 0 -> 0
        |
        +---- Group 1 -> 1
        |
        +---- Other -> Skip
        |
        v
    Extracted Bitstream
        |
        v
    Huffman Decoding
        |
        v
    Recovered Secret Message

# Method 2 - Single Character-Based Word Generation

## Description

Method 2 uses a character-to-word generation approach.

Instead of converting the secret message into bits, each character is directly
represented by a generated word.

For example, if the secret character is:

    v

the LLM must generate a meaningful word beginning with:

    v

Similarly:

    e -> elegant
    n -> natural
    k -> kinetic
    a -> amazing

The first character of each generated word is used during extraction.

---

## Method 2 Embedding Process

The process is:

    Secret Message
          |
          v
    Character Sequence
          |
          v
    LLM Word Generation
          |
          v
    Word Beginning With Required Character
          |
          v
    Stego Text

The LLM is given the current context and the required character.

The generated word must:

- Start with the required character
- Be a meaningful English word
- Fit the surrounding context
- Avoid unnecessary repetition

If the generated response does not satisfy the required first-character
constraint, another generation attempt is made.

The current implementation allows multiple attempts before producing the
next encoded word.

---

## Method 2 Extraction

The first character of every encoded word is extracted.

For example:

    venerable
    elegant
    natural
    kinetic
    amazing

produces:

    venka

The extraction process is:

    Stego Text
        |
        v
    Encoded Words
        |
        v
    First Character of Each Word
        |
        v
    Recovered Secret

---

# Evaluation Metrics

The two methods use different primary embedding-capacity metrics.

## Method 1

The main metrics are:

- BPW
- BPC
- Log PPL
- Execution Time

### BPW - Bits Per Word

Bits Per Word represents the average number of hidden bits embedded per
generated word.

    BPW = Number of Hidden Bits / Number of Words

A higher BPW indicates greater embedding efficiency.

### BPC - Bits Per Character

Bits Per Character represents the average number of hidden bits embedded
per character in the stego text.

    BPC = Number of Hidden Bits / Number of Characters

BPC provides a character-level measurement of embedding efficiency.

### Log PPL - Log Perplexity

Log Perplexity is used to estimate the predictability of the generated text.

Lower values generally indicate more predictable generated text, while higher
values indicate greater uncertainty.

### Execution Time

Execution time measures the time required for embedding, extraction, and
metric calculation.

---

# BPW and BPC Trade-off

One of the important observations made during the implementation and
experimentation is the **trade-off between BPW and BPC**.

The two metrics do not necessarily increase together.

In practical experiments, increasing the number of bits embedded per word can
affect the number of characters required to represent those bits. Similarly,
optimizing character-level capacity can affect word-level capacity.

Therefore, BPW and BPC can exhibit a **see-saw-like trade-off**:

    Increasing one
          |
          v
    can reduce the other

and vice versa.

This means that maximizing only one metric does not necessarily produce the
best steganographic text.

The goal is instead to find a suitable balance between:

    Embedding Capacity
          +
    Text Naturalness
          +
    Extraction Accuracy

This trade-off is an important observation from the implementation and
experimentation.

---

# Method 2 Metrics

Method 2 does not convert the secret message into a binary bitstream.

Therefore, BPW and BPC are not the primary metrics for this approach.

Instead, Method 2 uses:

- CpW
- PPL
- Execution Time

### CpW - Characters per Word

CpW represents the relationship between the secret characters and generated
words.

Since one generated word represents one secret character in the current
implementation, the documented experiments achieve:

    CpW = 1.0

### PPL - Perplexity

Perplexity is used as an indicator of generated-text quality and
predictability.

Lower perplexity generally indicates more predictable and fluent language
according to the language model used for evaluation.

# Limitations

The current implementation has several limitations.

1. LLM generation can require multiple attempts to satisfy the embedding
   constraints.

2. Method 1 may require considerable generation time because candidate words
   are generated and evaluated against the remaining bitstream.

3. Method 2 requires approximately one generated word for every secret
   character.

4. Longer secret messages can make it more difficult to maintain natural
   language.

5. There is a trade-off between embedding capacity and generated-text
   naturalness.

6. The current implementation is intended primarily as a research and
   experimental prototype.
